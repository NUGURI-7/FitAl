# FitAl iOS QA

> 纯问答体,面向"别人问项目细节"。每答重点:为什么这么做、为什么不那样做。
> 每完成一个功能块顺手补条目。Web 见 frontend-qa.md,后端见 backend-qa.md。

分节:一、路线与分发 二、工程 三、体验与性能

---

## 一、路线与分发

**Q1: 没有付费开发者账号,app 是怎么装到手机上的?有什么代价?**
A: 走免费签名路线:用普通 Apple ID 在 Xcode 里生成"个人团队"开发证书,数据线配对+手机开开发者模式+信任开发者,之后 Xcode 直接把 app 推进手机(配好后同一 Wi-Fi 可无线装)。代价三条:签名 7 天过期,到期 app 打不开,重按一次运行键续签(数据都在服务器,重装不丢任何东西);同时最多 3 个自签 app;TestFlight 不可用——它必须付费开发者账号(99 美元/年),所以朋友短期继续用 Web 链接,将来真要分发再考虑充值,代码零改动。

**Q2: 为什么最低系统版本锁 iOS 26,不降到 18/17 覆盖更多设备?**
A: 液态玻璃这套设计语言只在 iOS 26 上存在。若最低版本设 18,所有玻璃效果和新动画处处要写版本分支、再配一套旧系统备用样式——等于 UI 做两遍。而现实是这 app 只装在用户自己一台 iPhone(26.x)上,朋友走 Web,不存在旧系统用户:降版本换不来一个真实用户,却付双倍 UI 成本。将来要分发时按当时朋友们的系统版本再议。另一个坑:工程模板默认锁 SDK 同版本(26.5),比手机系统(26.2.1)还高导致装不进,实际定为 26.0。

## 二、工程

**Q3: iOS 端怎么连后端?后端部署上云之后要改哪里?**
A: 开发期手机和 Mac 在同一 Wi-Fi,app 直连 Mac 的局域网地址(Mac 上跑着后端,数据库本来就在云端,链路=手机→Mac→云库)。地址硬编码在接口层一处,上云只改这一个常量。局限也明确:出门在外或 Mac 睡觉就连不上,所以"随时随地用"最终要靠后端上云;Mac 的局域网地址被路由器换掉时也要跟着改。接口契约与 Web 完全同一套(/days、/weights、/chat SSE、改删),口径换算(净摄入=摄入−折算基础代谢−运动净耗、今天的基础代谢按已过分钟折算)也照抄 Web 的算法,两端永远同数。

**Q4: App 图标是怎么做出来的?想换怎么办?**
A: 没有设计师,用代码画:一个脚本(scripts/icon_gen.swift)用系统绘图能力渲染 1024 图——墨绿渐变底 + 前倾圆体"Fit"字标 + i 的点换暖橙(呼应数据双色)+ 底部上扬速度弧线,前景做了像素级扫描居中。过程是候选驱动:三轮共五个候选(居中字标/大字出血/衬线斜体/极光背景/圆环背景),用户挑中一版。想换图标=改脚本重跑,生成的图直接覆盖进图标资源槽。坑:视网膜屏下脚本输出实际是 2048 像素,图标槽严格要求 1024,要先压缩;曾试过的"手写飘带"三连败,教训是无参照手绘曲线细节极易翻车,经典构图(底划弧线)一次就成。

## 三、体验与性能

**Q5: 为什么把"会呼吸的背景"和发送键微光这些循环动画砍了?当初不是 To C 动效清单里的吗?**
A: 两轮教训后砍定。第一轮:柔光当初用"大圆+高强度模糊+永久循环"实现,模糊是 GPU 最贵操作之一,循环意味着屏幕永不休息——发烫、掉帧都有它一份,后来换成径向渐变(视觉几乎无差,成本差几十倍)。第二轮:就算渐变很便宜,"永久循环"本身仍让 GPU 永远醒着,费电;而 9 秒漂一次的背景肉眼几乎注意不到,性价比为负。行业惯例也是如此:消费级 app 的动效全是"响应式"——操作才动、动完即静,常驻装饰动画属于淘汰做法。最终原则入档:动效只做响应式(入场浮现/数字滚动/按压回弹/发送爆光保留),不做常驻循环。

**Q6: 真机上偶发"打开就卡死"是怎么回事?查到哪一步了?**
A: 悬案,现状如下。现象:偶发打开 app 全屏不可点,重装即愈,过后复发。已排除:代码死循环(同代码同后端在模拟器反复跑均正常、数据秒出);常驻动画(砍光后仍复发)。已加固:读接口 10 秒超时——此前网络请求默认可挂 60 秒,若网络路不通,满屏空白转圈看起来就是"卡死",现在最多 10 秒进"连不上服务器+重试"页。头号嫌疑:手机上的代理工具把发往局域网的请求吞进隧道黑洞化(模拟器不经手机代理,恰好解释"模拟器永远正常");待用户关代理对照验证。若再现:不重装,连 Xcode 用调试器暂停抓主线程栈,一次定案。附带认知:调试版(Xcode 运行键装的包)本身比正式版慢一截,判断真实流畅度要切 Release 构建。
