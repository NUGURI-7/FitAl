# FitAl 产品文档

> 产品视角的单一事实来源:这个 app 是什么、给谁用、做什么、不做什么。
> 技术架构与工作规则见 `../CLAUDE.md`,当前进度见 `context.md`。

## 一句话定位

输入一句话——"我刚做了20个俯卧撑"/"中午吃了200克鸡胸肉"——app 自动把它变成结构化的运动/饮食记录,并汇总每日摄入与消耗。

## 目标用户

- 作者本人 + 少量朋友(个位数用户)
- 有记录习惯、但嫌传统热量 app 录入繁琐的人:不想在几十个下拉框里找"俯卧撑"、不想查食物库填克数表单

## 核心体验原则

1. **录入零门槛**:一句自然语言,不选分类、不填表单
2. **只记录,不指导**:绝不输出"你今天吃多了"之类的建议、计划、教练内容
3. **数据可信、可修**:每条记录标注数据来源(用户自报 / 查表 / AI 估算,三者视觉可区分),解析错了可以直接改数字
4. **聚合是程序的事**:用户只管一句一句正常说(练完一组说一组、吃完一顿说一顿),场次识别、时长推断、每日汇总全部由后端自动完成,绝不要求用户配合系统补充信息

## 核心用户流程

### 记录(高频,每天数次)

1. 输入一句话:"跑了半小时" / "吃了一碗米饭和两个鸡蛋"
2. app 解析出一条或多条记录(一句话可含多条),展示热量等数值和数据来源
3. 发现解析不对 → 直接修正数字

### 查看(每天 1-2 次)

- 当日摄入总热量 / 消耗总热量 + 记录列表
- AI 估算的记录在视觉上可辨识(与查表/自报区分)

### 用户切换(暂缓)

- 无注册登录;单人使用期前端固定用户,不做选人界面;真有朋友用再加"列人选人"(2026-07-06 定)

## 功能范围

### 做

- 自然语言 → 运动/饮食/体重结构化记录
- 复合菜拆解(番茄炒蛋 → 番茄、鸡蛋等多条食材记录;用户通常自报食材量,拆解是兜底)
- 每日摄入/消耗汇总;餐次/力量场次由 AI 在解析时归组并起名(无时间阈值)
- 体重变化曲线
- 记录修正(手动改数字)
- 多用户(简单选择,非账号体系)

### 不做(硬边界,对应 CLAUDE.md 架构决策)

- 不做建议 / 计划 / 教练 / 提醒
- 不做社交、分享、排行
- 不做身高/体脂/BMR/TDEE 等身体指标体系,只用体重
- 不做注册登录
- 不做商业化,无并发考量

## 典型输入 → 期望结果

| 用户输入 | 期望结果 |
|---|---|
| "我刚做了20个俯卧撑" | 1 条运动记录:俯卧撑按次数换算成时长,MET 查表计算消耗(`met_table`) |
| "吃了200克鸡胸肉" | 1 条饮食记录:映射到"鸡胸脯肉"查表,按克重算热量/蛋白质等(`food_table`) |
| "中午吃了番茄炒蛋" | 多条饮食记录:LLM 拆解为番茄、鸡蛋等食材并估重,标 AI 估算(`llm_estimated`) |
| "跑步40分钟,大概消耗300千卡" | 1 条运动记录:直接采用用户自报的 300 kcal(`user_reported`) |
| "吃了个楼下的猪脚饭" | 1 条饮食记录:表里没有 → LLM 整体估算,标 AI 估算(`llm_estimated`) |
| "番茄200克 鸡蛋100克 炒的"(没报油) | 3 条记录:番茄、鸡蛋查表 + 自动补"烹调油约10g"(AI 估算,显式独立成条,可删) |
| "今天75公斤" | 1 条体重记录,体重曲线与消耗计算随之更新 |
| 12:03"米饭200g",12:06"鸡蛋100g" | 2 条独立记录,AI 判断归入同一顿并起名 |

## 客户端形态

- **第一步:后端 API**,curl 即可自用(已完成)
- **第二步:Web**(进行中):设计从 iOS app 出发,Web 是该设计的轻量快速实现;纯手机宽度,不做 PC 适配;技术栈 React+Vite+Tailwind+shadcn/ui+Lucide+ECharts
- **第三步:iOS 原生 app(SwiftUI)为主产品**,不设 deadline
- **远期**:安卓原生,有真实安卓用户再评估;当前不设计、不预留

## Web v1 页面形态(2026-07-07 与用户定稿)

**单页应用**,自上而下:

1. **顶部**(常驻):日期切换(左右箭头,可回"今天")+ 当日汇总条——摄入 / 消耗 / 体重三个数;**点体重格 → 底部滑出全屏体重曲线面板**(近 30 天)
2. **中间**:当日记录流——每顿饭 / 每场训练一张卡片(AI 起的名 + 时段 + 总热量),点卡片展开明细条目;**点明细 → 底部抽屉**(该条全部信息 + 改数字 + 删除),改完卡片数字即时刷新;数据来源(自报/查表/自定义/AI估算)在明细上视觉可辨
3. **底部**(固定):一句话输入框,发送即记录,新卡片即时出现在记录流;语音按钮待流式 STT 接入后加

交互语言统一:一切详情与操作 = 底部抽屉;全 app 仅此一页。

**第二批**(不阻塞 v1):设置页——改身体档案、查看/删除自定义食物与 AI 记忆(需配套新后端接口);模型配置界面永久不做。
