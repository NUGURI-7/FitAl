## 记录越用越准·沉淀机制(2026-08-22)

**动机**:用户提出"准确率不够 + 产品太单薄"。查证后定性——准确率的大头不在解析管线,
在数据源(官方 1595 条是原料表,日常吃的"一碗兰州拉面""达美乐披萨"永远查不到,只能估);
而"单薄"的根子是**这个工具不记得你**,用一个月和用一天完全一样,没有任何东西在积累。
结论:主流 app 强在覆盖率不在精度(UGC 库同一样东西十几个数),真正该追的是**记稳**不是记准——
同一样东西每次同一个数,趋势才成立。

**做完三件事**:

1. **删记录不再学"纠正"**(提交 4b03a4c)。一次删除含义多义(记重了/没吃/试一下/确实估错),
   统一当成"AI 估错了"是把噪音当知识;学出来的"用户删除了X"是动作日志,注入解析提示词后
   模型无从行动,还反向压制补油补调味。线上四条存量垃圾已清空(备份在案)。
   改热量那条学习路径保留——那是用户给出了正确答案,真信号。

2. **改热量沉淀进个人食物库**(本次主体)。你改过一次的东西,以后直接命中不再估。
   两种口径二选一:**有量词按份存**("一碗=250千卡",克数不参与——整份食物的克数是模型
   倒填的,拿它当分母会把噪音固化);**无量词按每100克存**。改克数不沉淀、删除不沉淀、
   查表命中的记录改了也不沉淀;同名同量词重复改按新值覆盖。
   **量词不归一**(碗/份/根各存各的,用户说话有惯性,几次自然收敛)。
   迁移 0011-0013:记录表加量词/数量/原话叫法三列,食物库加量词与每份热量、唯一键
   改 (用户,名字,量词)。**量词列刻意不可空(空串=每100克口径)**——两方言的唯一约束都把
   NULL 视为互不相等,可空会让"重复记住即更新"退化成插多条。三端设置页按口径显示。

3. **修两个真 bug**(都是真实数据里抓出来的):
   - **估算热量漏乘数量**:"两碗大米饭"克数乘了 2、热量没乘,记成一碗(400g/232千卡,
     真实 464)。根因=加"数量"字段时只改了克数的说明、没改热量的,"该份"在两边被读成
     不同意思。修法按决策9走结构:字段改名为自带"一份"语义,代码把热量与克数走同一条
     乘法;用户自报热量不乘(那是总数)。干净估算的问法也写死"只估一份"。
   - **"一碗"被粘进食物名**:模型对"两碗/三碗"能剥干净,对"一碗"稳定剥不掉
     ("一碗大米饭"读起来像整体名字,三次全这样),导致存"大米饭"、查"一碗大米饭"
     永远对不上。修法=量词已是代码拿到的确定值,据它确定性剥前缀(可单测,
     "碗仔翅"这类量词开头的真名字不误伤)。

**验证**:181 单测全过;连生产库跑完整闭环(记一句→改热量→沉淀→四种说法全部命中,
250/250/750/500 全对),验证数据已清理;三端编译通过。
